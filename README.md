# Практическая работа №2. Вариант 30

Инструмент строит граф зависимостей пакета Ubuntu APT и выводит его в
формате D2. Данные читаются напрямую из индекса `Packages` либо из
локального тестового графа. Утилита не запускает APT, dpkg или другой
менеджер пакетов; штатный APT используется отдельно для сравнения.

## Запуск

Требуется Python 3.10 или новее. Сборка и установка модулей не нужны.
Откройте папку проекта, где лежат `run.bat`, `config.yaml` и `src`.
В Windows, в том числе в терминале PyCharm с PowerShell:

```powershell
.\run.bat
```

В Linux/macOS:

```sh
sh run.sh
```

По умолчанию печатается D2 для тестового пакета A. Интернет не нужен.
В PyCharm также можно создать конфигурацию Python с **Module name**
`apt_graph`, рабочей папкой проекта и переменной `PYTHONPATH=src`.

## Настройки YAML

| Поле | Назначение |
| --- | --- |
| `package` | Имя пакета: A..Z для тестов или имя пакета APT. |
| `repository` | HTTP(S) URL зеркала/индекса или путь к тестовому JSON. |
| `test_mode` | `true` для JSON, `false` для индекса Ubuntu. |
| `version` | Точная версия пакета; указывайте в кавычках. |
| `max_depth` | Целое 0..256; 0 оставляет только корень, 1 - прямые связи. |

Пример `config.yaml`:

```yaml
package: A
repository: examples/repository.json
test_mode: true
version: '1.0'
max_depth: 3
```

Поддерживается плоское YAML-отображение: пять строк `ключ: значение`,
обычные и заключённые в кавычки строки, десятичные целые, `true`/`false`,
пустые строки и комментарии. Для двойных кавычек действуют экранирования
JSON. Вложенные структуры, якоря и многострочные значения не нужны
для этой схемы и не поддерживаются. Лишние и повторные ключи - ошибки.
Относительный путь к тестовому JSON считается от файла YAML.

Для URL зеркала без имени индекса используется путь
`dists/noble/main/binary-amd64/Packages.xz` (Ubuntu 24.04, main, amd64).
Чтобы выбрать другой выпуск, компонент или архитектуру, укажите полный
URL его `Packages`, `Packages.xz`, `Packages.gz` или `Packages.bz2`.
За один запуск читается один индекс. Для сетевого режима нужен доступ
к указанному зеркалу. Индекс сжимается в архиве, но пакеты не скачиваются.

## Режимы вывода

| Аргумент | Действие |
| --- | --- |
| `--config PATH` | Выбирает YAML вместо `config.yaml`. |
| `--mode config` | Печатает пять параметров `ключ=значение`. |
| `--mode direct` | Печатает `Depends` и `Pre-Depends` точной версии. |
| `--mode graph` | Печатает список рёбер, глубину и неразрешённые группы. |
| `--mode order` | Печатает зависимости перед пакетами, которым они нужны. |
| `--mode d2` | Печатает D2; это режим по умолчанию. |
| `--output PATH` | Дополнительно сохраняет вывод в текстовый файл UTF-8. |
| `--help` | Показывает справку. |

В режиме `direct` альтернативы показаны через `|`, вместе с ограничениями
версий. Неправильные параметры, недоступный источник, ошибки формата и
отсутствующая версия выводятся в stderr. Коды: 0 - успех, 1 - ошибка
данных или доступа, 2 - неправильные аргументы CLI.
Неразрешённая зависимость отмечается в отчёте и D2, сохраняя частичный граф.

```powershell
.\run.bat --mode config
.\run.bat --config examples/ubuntu/hello.yaml --mode direct
.\run.bat --config examples/cycle.yaml --mode order
.\run.bat --config examples/ubuntu/sed.yaml --output sed.d2
```

В `examples/errors` есть пять YAML с ошибками: неверное имя пакета,
отсутствующий файл, неправильный режим, неверная версия и отрицательная
глубина. Например:

```powershell
.\run.bat --config examples/errors/max-depth.yaml --mode config
```

## Тестовый репозиторий и DFS

Формат JSON: пакет → версия → список прямых зависимостей. Пакеты
называются заглавными латинскими буквами. Пример:

```json
{"A": {"1.0": ["B"]}, "B": {"1.0": []}}
```

| Конфигурация | Что проверяет |
| --- | --- |
| `config.yaml` | A → B и C, у обеих вершин общая D. Порядок D, B, C, A. |
| `examples/shallow.yaml` | Только один уровень: B, C, A; D не попадает в граф. |
| `examples/cycle.yaml` | E → F → E. Цикл сохраняется; строгого порядка нет. |
| `examples/isolated.yaml` | Один пакет G без рёбер. |

Поиск в глубину реализован рекурсивно. Вершина идентифицируется именем,
версией и архитектурой. Если вершина найдена повторно по более короткому
пути, оставшийся предел глубины увеличивается и её рёбра пересматриваются.
Повтор с такой же или большей глубиной не вызывает новой рекурсии.
Рёбра цикла сохраняются. В режиме порядка используется обход с выходом
из вершины после её зависимостей; цикл выводится отдельной строкой.
Список при цикле означает порядок DFS после разрыва обратного ребра.

При анализе APT учитываются только обязательные связи. Для каждой
группы выбирается первая доступная альтернатива. Внутри её реального
пакета берётся наибольшая допустимая версия по правилам Debian; если
реального кандидата нет, проверяются записи `Provides`. Из нескольких
провайдеров выбирается первый по имени, затем наибольшая версия.
Учитываются явные архитектуры, `:native` и `:any` в пределах индекса.
Алгоритм не решает задачу установки: не проверяет `Conflicts`, приоритеты
APT, установленные пакеты или глобальную совместимость версий.

## Три графа и сверка с APT

Готовые исходники D2 в `examples/diagrams`: `hello.d2`, `grep.d2`,
`sed.d2`. Версии заданы в одноимённых YAML в `examples/ubuntu`.
SVG можно открыть в браузере; для повторной отрисовки нужен D2:

```sh
d2 examples/diagrams/hello.d2 hello.svg
d2 examples/diagrams/grep.d2 grep.svg
d2 examples/diagrams/sed.d2 sed.svg
```

Сверено со штатным APT 2.8.3 в Ubuntu 24.04. На одинаковом индексе
совпали наборы пакетов и обязательные рёбра всех трёх графов. У `hello`
совпал порядок; у `grep` и `sed` поменялись местами `libc6` и `libgcc-s1`.
Их связи образуют цикл, поэтому DFS и APT могут разорвать его по-разному.
Подробности и воспроизводимые команды - в `examples/APT-COMPARISON.md`.

## Проверки

В PowerShell из папки проекта:

```powershell
$env:PYTHONPATH = 'src'
py -3 -m unittest discover -s tests -v
```

В Linux/macOS:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Проверяются ошибки пяти параметров, сжатие индексов, точный выбор версии,
альтернативы, `Provides`, циклы, предел глубины, порядок и вывод D2.
Модульные тесты работают без сети. Сетевой режим проверен отдельным
запросом к официальному архиву Ubuntu.

## Устройство проекта

- `__main__.py`: `main` читает CLI и печатает результат, `analyze`
  выбирает источник и режим анализа.
- `errors.py`: `InputError` хранит понятные пользователю ошибки.
- `yaml_config.py`: `parse_scalar` и `parse_mapping` читают простую YAML;
  `read_mapping` открывает файл UTF-8.
- `config.py`: `Config` хранит параметры, `dump` печатает их;
  `check_fields` проверяет ключи, `require_string` - строки;
  `validate_url`, `validate_source`, `load_config` проверяют настройки.
- `apt_source.py`: `index_url` строит URL, `download_index` читает его,
  `decode_index` распаковывает данные, `load_apt` создаёт каталог.
- `deb822.py`: `parse_paragraphs` читает блоки полей и переносы строк,
  `read_records` превращает их в записи пакетов.
- `records.py`: `PackageId`, `Record` и `Catalog` хранят метаданные;
  `describe` форматирует пакет, `relations` возвращает связи,
  `exact` находит точную версию. Каталог строит индекс по именам.
- `relations.py`: `Dependency` и `Relation` хранят обязательства и
  альтернативы; `describe`, `parse_dependency`, `parse_relations`
  печатают и разбирают поля зависимостей.
- `test_source.py`: `load_fixture` читает JSON; `unique_object` отвергает
  повторные ключи, `fixture_records` и `fixture_versions` проверяют схему.
- `versions.py`: `split_version` делит Debian-версию на три части;
  `compare_values`, `digit_key`, `letter_rank`, `compare_letters`,
  `compare_parts` реализуют сравнение фрагментов. `compare_versions`
  сравнивает полные версии, `satisfies` проверяет ограничение.
- `resolve.py`: `Resolver` индексирует провайдеров. `architecture_ok`
  проверяет архитектуру, `select` и `compare_records` выбирают версию,
  `candidate` ищет пакет или провайдера, `resolve` выбирает альтернативу.
- `graph.py`: `Graph` хранит вершины и `Edge`; `GraphBuilder.build`
  запускает рекурсивный `visit`, `describe_graph` печатает граф.
- `order.py`: `Ordering` хранит список и циклы; `dependency_order`
  строит порядок, `describe_order` готовит читаемый отчёт.
- `d2_output.py`: `quote` экранирует текст, `package_label` строит подпись,
  `unresolved_lines` обозначает пропуски, `to_d2` сериализует граф.

Исходники находятся в `src`, тесты в `tests`, конфигурации, D2 и
эталонный скрипт в `examples`. Скрипты `run.bat` и `run.sh` запускают
пакет Python. `.gitignore` исключает кэш, файлы IDE и результаты сборки.

В истории пять отдельных коммитов: конфигурация, APT, DFS, порядок и D2.
Просмотр: `git log --oneline`. Для сдачи этот проект можно опубликовать
в отдельном публичном репозитории после проверки.
